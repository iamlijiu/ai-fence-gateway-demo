AI安全围栏 — 一期范围表（建议稿）

编制依据：《AI安全围栏建设方案.docx》v2 中 1.3 系统设计目标、2.3.1 功能全景、2.3.2 功能详细描述
编制原则：
1. 一期 = 上行链路敏感数据完全管控（P0）+ 必要的支撑能力；
2. 存在矛盾处按"业务诉求 → 功能实现 → 运维可行性"自洽原则调和（详见 D1~D6 决策点）；
3. 凡标注【需确认】的行，需业务方/技术方拍板后定稿。

二、一期 / 二期 / 搁置 汇总

一期交付（P0 主链路 + 支撑）

  • 主链路：报文解析（Header/Body/嵌套/Prompt）→ 规则匹配（字段路径+正则、9 类敏感信息、scope、优先级）→ 敏感请求管控（掩码/替换/删除/拦截/重组）→ 异常降级（reject/passthrough）
  • 支撑：统一请求标识（提升 P0）、脱敏操作日志（提升 P0）、规则配置最小形态 + 热加载（≤1 秒）、基础监控与告警

二期交付（P1）

  • 接入鉴权增强（统一流式/非流式地址、业务方/接口/模型识别）
  • 一致占位符 / 返回后还原（机制评审通过后）
  • 下行链路全套：异步检测 → 内容安全检测（含高风险同步、安全改写）→ 结果反馈（3 模式）→ 违规记录与告警复核
  • 规则管理完整版：灰度发布、回滚、版本化
  • 管理后台完整版、完整多维统计报表
  • "提示"降级模式、XML/gRPC 扩展

搁置（P2）

  • 加密脱敏（依赖密钥管理方案）
  • 多模态数据解析
  • 完整统计报表

编号决策点现状建议影响

D3"一致占位符 / 返回后还原"是否进一期v2 列为 P0（含在敏感请求管控模块）建议二期：跨会话泄露、映射生命周期、流式还原等机制未设计，硬塞一期风险高影响一期验收标准与风险敞口
D49 类敏感信息清单确认只提"9 类"未列清单业务方+安全确认 9 类清单及默认规则/处置决定初始规则集内容
D5分场景性能指标确认需求"放宽为分场景"，2.4.1 仍是统一 50ms按场景出指标表（如设备之家高并发 vs 内部问答）决定压测达标口径
D6一期不做下行检测是否可接受背景列为核心问题之一，但模块标 P1与业务方确认一期仅上行管控、下行二期决定一期交付边界

五、配套待办（随一期范围表一并落实）

  1. 上轮 P0 未决项需在一期设计阶段补齐：规则存储主从与热加载机制（P0-1）、异常降级执行载体与旁路观察模式（P0-7）、密钥管理（P0-5，影响加密脱敏与模型 API Key）；
  2. 一期规则最小形态确定后，同步更新 2.3.2 规则 JSON 示例（补 disposition 字段）与 desensitization_rule 表（上轮 N2/P0-6）；
