# AI安全围栏建设方案

# *1\. 背景\&调研\&目标*

## *1\.1\. 需求背景*

随着人工智能技术在金融领域的深入应用，我司各业务系统广泛对接外部AI模型以提升服务效能，随之而来的敏感数据泄露风险及合规要求却未能及时建设。因此，在开放平台建设AI安全围栏，统一管控AI调用链路，已成为保障金融业务安全、稳定、合规发展的当务之急。

**主要****问题**

- 上行报文中包含用户隐私数据（手机号、身份证、邮箱等）、企业内部敏感信息（API Key、内部 IP、商业数据等），缺乏统一的脱敏机制，数据直接透传至 AI 模型侧

- 模型返回内容缺乏检测，可能涉及脚本注入和涉政、涉黄、涉恐等违规内容

## 2\.1 方案对比与选型

### 2\.1\.1 方案概述

针对网关层上行脱敏需求，提出以下候选方案进行对比：

|维度|方案A：基于现有网关集成|方案B：新建独立脱敏服务|
|---|---|---|
|**方案描述**|在现有网关组件中新增脱敏插件/模块|在网关与 AI 模型之间新建独立的脱敏微服务|

### 2\.1\.2 详细对比

|对比维度|方案A：现有网关集成|说明|方案B：新建脱敏服务|说明|
|---|---|---|---|---|
|**开发成本**|低,1\~2周|直接在现有工程加入脱敏模块|中。3\~4周|独立微服务，需技评等|
|**运维成本**|低|不新增运维成本<br>|高<br>|需管理新服务的部署、监控、日志收集|
|**性能影响**|低|同进程方法调用，耗时在10ms内|中<br>|多一层RPC调用；还需考虑网络抖动和GC|
|**可扩展性**|低|原有老的技术架构，升级困难|高|新架构，无负担扩展|
|**迭代周期**|前期短；中后期长||前期较长；中后期短||
|**与现有架构兼容性**|原应用集成无兼容问题||兼容||
|**技术栈要求**|Java springboot||springboot,mq,prometheus等||
|**风险点**|与原有应用耦合，影响其他功能||开发周期长、人力不足||

### 2\.1\.3 选型结论

**选型结论：推荐方案A（现有网关集成）**

理由：

- 当前阶段以快速落地、满足业务诉求为优先

- 采用模块化设计，脱敏逻辑独立封装，后续可平滑迁移为独立服务

- 无需新增基础设施，复用现有网关、配置中心、数据库

**演进路线：**

- **第一阶段**：在现有网关中集成脱敏模块，做好模块化隔离

- **第二阶段（待定）**：当脱敏规则频繁变更、多业务方复用、或职责扩展（如下行内容审查）时，拆分为独立服务

### 2\.3\.2 功能详细描述

#### 规则配置

**描述**：管理员可通过管理后台或 API 配置脱敏规则。

**规则定义示例**：

```JSON
{
  "rule_id": "rule_001",
  "rule_name": "手机号脱敏",
  "match_type": "regex",
  "match_pattern": "1[3-9]\\d{9}",
  "field_path": "$.phone_number",
  "mask_strategy": "mask_middle",
  "mask_config": {
    "keep_prefix": 3,
    "mask_char": "*",
    "keep_suffix": 4
  },
  "priority": 1,
  "enabled": true,
  "scope": {
    "routes": ["route_ai_chat", "route_ai_completion"],
    "consumers": ["app_system_a", "app_system_b"]
  }
}
```

**验收标准**：

* [ ] 支持通过 API 创建/修改/删除/查询脱敏规则

* [ ] 规则变更后 ≤ 【1】秒内生效

* [ ] 规则配置支持校验，非法配置拒绝保存

#### 掩码脱敏

**描述**：对匹配到的敏感字段进行部分遮蔽处理。

**脱敏效果示例**：

|数据类型|原始值|脱敏后|
|---|---|---|
|手机号|13812341234|138\*\*\*\*1234|
|身份证|110101199001011234|110101\*\*\*\*\*\*\*\*1234|
|邮箱|test@example\.com|t\*\*\*@example\.com|
|银行卡|6222021234567890|6222\*\*\*\*\*\*\*\*7890|

**验收标准**：

* [ ] 非匹配内容不受影响

# *3\. 接口设计*

### 3\.1 脱敏规则管理接口

#### 3\.1\.1 创建脱敏规则

```Plaintext
POST /api/v1/desensitization/rules
```

**请求体**：

```JSON
{
  "rule_name": "手机号脱敏",
  "match_type": "regex",
  "match_pattern": "1[3-9]\\d{9}",
  "field_path": "$.phone_number",
  "mask_strategy": "mask_middle",
  "mask_config": {
    "keep_prefix": 3,
    "mask_char": "*",
    "keep_suffix": 4
  },
  "priority": 1,
  "scope": {
    "routes": ["route_ai_chat"],
    "consumers": []
  }
}
```

**响应**：

```JSON
{
  "code": 0,
  "message": "success",
  "data": {
    "rule_id": "rule_001",
    "created_at": "2026-07-09T10:00:00Z"
  }
}
```

```Plaintext
GET /api/v1/desensitization/rules?page=1&page_size=20&route=route_ai_chat
```

```Plaintext

```

#### 3\.1\.4 删除脱敏规则

```Plaintext
DELETE /api/v1/desensitization/rules/{rule_id}
```

#### 3\.1\.5 启用/禁用脱敏规则


## 4\.4\. 异常处理

### 4\.4\.1 异常场景与处理策略

|场景编号|异常场景|处理策略|影响范围|
|---|---|---|---|
|01|脱敏规则配置中心不可用|使用本地缓存的最新规则继续脱敏；若缓存过期则按降级策略处理|规则更新延迟|
|02|报文解析失败（格式异常）|记录告警日志，按降级策略处理（拒绝/透传）|当前请求|
|03|脱敏规则匹配异常（正则超时等）|跳过该规则，记录告警日志|当前请求的该规则|
|04|脱敏执行异常|记录告警日志，按降级策略处理|当前请求|
|05|脱敏日志写入失败|异步重试，不影响主流程|日志完整性|

### 4\.4\.2 降级策略配置

|降级模式|行为|适用场景|
|---|---|---|
|reject|拒绝请求，返回错误码|安全要求高的场景|
|passthrough|透传原始报文，记录告警|可用性优先的场景|
