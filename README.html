ai-fence-gateway-demo

Tomcat + WebFlux 转发 AI 接口 Demo —— 用于与现有网关工程对齐对照。

技术栈与现有网关一致：Spring Boot 2.0.8 + WebFlux 5.0.5 + Tomcat，Java 8。提供 OpenAI 兼容的单一入口 POST /v1/chat/completions，按请求体 stream: true/false 分流：

stream转发方式返回形式
trueWebClient（响应式）SSE（text/event-stream）逐块返回
falseRestTemplate（阻塞）JSON 一次性返回

内置 Mock 上游（/mock/v1/chat/completions，OpenAI 兼容格式），无外部 API Key 即可端到端验证；接入真实供应商只需改配置。

✅ 已实测通过（本机 WSL 环境，JDK8 构建运行）：非流式 JSON 转发、流式 SSE 透传（3 段 + [DONE]）、ZL-OPENID 403 拦截均验证 OK；启动日志确认 Tomcat/8.5.37 承载 WebFlux（ReactiveWebServerApplicationContext）。

三、验证用例（curl）

1. 非流式（stream=false）→ 一次性 JSON

curl -s -X POST http://localhost:8080/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "ZL-OPENID: sbzj_device" \
  -d '{"model":"qwen-max","stream":false,"messages":[{"role":"user","content":"你好"}]}'
# 预期：{"id":"mock-json","model":"qwen-max","choices":[{"message":{...}}]}

2. 流式（stream=true）→ SSE 逐块返回

curl -N -s -X POST http://localhost:8080/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Accept: text/event-stream" \
  -H "ZL-OPENID: sbzj_device" \
  -d '{"model":"qwen-max","stream":true,"messages":[{"role":"user","content":"你好"}]}'
# 预期：3 段 data: {...}，最后 data: [DONE]

3. 鉴权拦截（无 ZL-OPENID）→ 403

curl -s -X POST http://localhost:8080/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"qwen-max","stream":false,"messages":[]}'
# 预期：403 {"code":403,"message":"ZL-OPENID invalid or missing"}

五、与现有网关的对比要点（对照检查清单）

维度Demo 实现请对照原项目确认
WebFlux 运行容器显式 TomcatReactiveWebServerFactory（webflux starter 默认带 Netty，Netty 优先，需显式声明 Tomcat 工厂）原项目是否同样显式 Tomcat？还是实际跑在 Netty？
流式转发WebClient + bodyToFlux(DataBuffer) + writeAndFlushWith（字节级 SSE 透传）原项目用 ResponseEmitter 还是 Flux？字节级透传 vs 逐行解析的取舍
非流式转发RestTemplate（阻塞）与原项目一致；注意 WebFlux 内阻塞调用会占用容器线程
鉴权插入点WebFilter（HIGHEST_PRECEDENCE，Controller 之前）原项目 Filter 链顺序、是否已有其他 Filter
单接口分流一个 /v1/chat/completions 方法内读 body stream 字段分流原项目是否同一接口分流，还是两个接口
OpenAI 兼容请求/响应按 OpenAI 格式透传，出站统一规范原项目对火山/阿里的差异处理（model 映射、鉴权 Header）

六、注意事项

  1. WebFlux + Tomcat：spring-boot-starter-webflux 默认用 Reactor Netty 作为服务器；要跑在 Tomcat 上必须像 HttpClientConfig 那样显式声明 TomcatReactiveWebServerFactory。若原项目没这么做，实际可能在 Netty 上运行——这会影响线程模型与压测结论，值得确认。
  2. 阻塞调用：非流式分支的 RestTemplate 是阻塞的，在 WebFlux 容器上会占用 Tomcat 线程；Demo 保持与现状一致，生产建议评估换 WebClient（非阻塞）。
  3. SSE 透传：Demo 用字节级透传（DataBuffer），最大程度保真（含 [DONE]、事件注释等）；若需要解析/改写 SSE 内容（二期下行检测、占位符还原），需改为按事件解析（ServerSentEvent 或自解析行）。
  4. Demo 未包含：脱敏规则引擎、disposition 处置、日志/指标、灰度开关——这些属于安全围栏插件本体，不在本转发 Demo 范围内。
  5. 构建环境备注：本机 Maven 的 settings.xml 配了 Windows 路径 localRepository（E:/maven_jar_space），在 WSL 下会失效；构建时用 -Dmaven.repo.local=/home/cbj/workspace/.m2repo 指定工作区内仓库。
